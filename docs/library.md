# Библиотека и профили PDF

Библиотека связывает PDF с НРИ, показывает первую страницу и реальные виды полей. Файл может относиться к нескольким системам. Привязка помогает найти материал; она не подтверждает применимость каждой механики к каждой редакции правил.

## Обычный путь

1. Запусти `uv run python scripts/pdf_form_web_editor.py --open-browser`.
2. Выбери систему и материал. Книга или памятка открывается для просмотра. У шаблона нажми «Создать рабочую копию».
3. Заполни текст, флажки и варианты ComboBox, при наличии подходящего поля добавь изображение. Сохрани и проверь рендер под полупрозрачными полями.
4. Для продолжения открой копию через «Мои PDF» или «Сменить PDF». Новая рабочая копия автоматически видна в выборе файлов.

«Добавить PDF в библиотеку» принимает файл, название, систему и вид материала. Можно зарегистрировать другую НРИ. PDF и каталог сохраняются локально; исходный файл не меняется. Профиль JSON необязателен. Без него редактор использует фактические поля формы. Печатный PDF и скан остаются для просмотра; создание полей поверх такого фона в этот сценарий не входит.

Текст, флажки и варианты ComboBox доступны для изменения, button-поля — для вставки изображений. Списки ListBox, радиокнопки, подписи и поля с флагом «только чтение» сохраняются без редактирования. Для новой формы проверь значения после повторного открытия и внешний вид страниц: наличие полей само по себе не гарантирует подходящие шрифты и геометрию.

## Владельцы данных

| Данные | Путь | Кто читает |
| --- | --- | --- |
| Публичные системы и материалы | `library/catalog.json` | CLI, web-библиотека, проверка |
| Публичные профили | `library/profiles/*.json` | PDF-ядро, библиотека |
| Личный каталог | `templates/local/library/catalog.json` | Те же инструменты; объединяется с публичным |
| Импортированные личные PDF | `templates/local/library/files/<система>/` | Просмотр и создание копий |
| Личные профили | `templates/local/library/profiles/*.json` | PDF-ядро, библиотека |
| Рабочие копии | `templates/local/characters/<система>/` | Редактор, CLI, доставка |

Личный каталог может ссылаться на уже существующие PDF внутри `templates/local/`; перемещать их не нужно. Вид `character` открывает такой заполненный лист напрямую. Остальные записи служат источниками для копирования. Рабочие копии выбираются в «Мои PDF», а не дублируются в каталоге шаблонов.

Импорт записывает PDF и необязательный профиль перед атомарной заменой личного каталога под общей блокировкой. При обычной ошибке записи новые файлы удаляются. Повтор одинакового импорта возвращает существующую запись. Создание копии использует снимок источника и общий механизм проверки версии `pdf_file_state`. Повтор с тем же ID запроса возвращает существующую копию, сохраняя правки. Новый запрос создаёт отдельный лист. Внезапное завершение процесса до записи каталога может оставить неиндексированный локальный файл; оно не заменяет исходник и опубликованный каталог.

## CLI

```bash
uv run python scripts/pdf_library.py list --system pathfinder-2e --kind template
uv run python scripts/pdf_library.py inspect /path/to/new-sheet.pdf
uv run python scripts/pdf_library.py add /path/to/new-sheet.pdf \
  --system fate-core --system-name 'Fate Core' --title 'Мой лист Fate'
uv run python scripts/pdf_library.py copy pf2e-remaster-ru-fillable
uv run python scripts/pdf_library.py check
```

`add` всегда сохраняет материал локально. Для существующей системы `--system-name` не нужен. `--kind` принимает `template`, `reference`, `rules`, `homebrew`, `character`. Для профиля добавь `--profile-json /path/to/profile.json`. `check` проверяет пути, связи систем, контрольные суммы исходников, типы полей, число страниц и совместимость профилей. У личных листов `character` контрольная сумма не фиксируется, поскольку содержимое меняется при заполнении.

## Формат каталога

```json
{
  "schema_version": 1,
  "systems": [{"id": "fate-core", "name": "Fate Core"}],
  "items": [{
    "id": "fate-character-sheet",
    "title": "Лист Fate Core",
    "systems": ["fate-core"],
    "kind": "template",
    "path": "templates/fate-core/character-sheet.pdf",
    "profile": null,
    "capabilities": {
      "pages": 1,
      "fields": {"Text": 2, "CheckBox": 1},
      "readonly_fields": 0,
      "sha256": "<результат inspect>"
    }
  }]
}
```

Это пример структуры, а не готовая запись существующего PDF. ID системы и материала используют латиницу, цифры и дефисы. Пути относительные, только внутри проекта; выход через `..` и внешние симлинки запрещён. Публичный каталог не принимает пути из `templates/local/`. При поручении опубликовать новый исходник помести его в `templates/<система>/` или `materials/<система>/`, добавь запись и свойства из `inspect`, затем выполни `check`. Обычный пользовательский импорт этой публикации не делает.

## Формат профиля

Профиль описывает имена полей и внешний вид формы. Он не хранит правила расчёта персонажа. Пример для PDF с полями `CharacterName` типа Text и `Prepared` типа CheckBox:

```json
{
  "schema_version": 1,
  "id": "fate-example",
  "system": "fate-core",
  "required_fields": ["CharacterName", "Prepared"],
  "text_markers": ["Fate Core"],
  "text_fields": {"hero": "CharacterName"},
  "checkbox_fields": {"prepared": "Prepared"},
  "image_fields": [],
  "compact_rows": [],
  "equal_font_groups": {}
}
```

`required_fields` обязателен и непустой. `text_markers` проверяется на первой странице; выбирай маркеры, отличающие версию листа. Карты `text_fields` и `checkbox_fields` задают логические имена; целевые поля и их типы проверяются до записи. `image_fields` задаёт предпочтительные button-поля, если они есть. `compact_rows` и `equal_font_groups` принимают регулярные выражения для согласованного размера текста. Остальные поля, кроме версии, ID, системы и `required_fields`, можно опустить.

Профиль распознаётся по всем обязательным полям и маркерам. Совпадение нескольких профилей считается ошибкой: уточни признаки формы. Повтор ID с другим содержимым также отклоняется. Web-редактор всегда сохраняет фактические имена; логические имена предназначены для программного заполнения. Префикс `raw:` обходит сопоставление.

## Границы кода и выбор языка

`template_profiles.py` владеет загрузкой и проверкой профилей. `pdf_library.py` владеет каталогом, импортом и копиями. `pdf_library_web.py` строит библиотеку на общей оболочке редактора. `pdf_form_editor.py` владеет PDF-полями и рендером; `pdf_file_state.py` — безопасной публикацией файлов. CLI, web и доставка используют это ядро.

Оставлен Python и существующий PyMuPDF. Нужный путь уже объединяет [чтение и изменение widgets](https://pymupdf.readthedocs.io/en/latest/widget.html), [рендер страниц и работу с изображениями](https://pymupdf.readthedocs.io/en/latest/tutorial.html). Go-инструмент [pdfcpu](https://pdfcpu.io/form/form_fill/) предлагает операции с формами, но полная замена потребовала бы заново подтвердить локализованные сопоставления, шрифты, изображения и доставку. Выигрыш производительности для текущего сценария не измерен. Поэтому переписывание не оправдано этой задачей; новый независимый сервис с существенной логикой можно оценивать отдельно.
